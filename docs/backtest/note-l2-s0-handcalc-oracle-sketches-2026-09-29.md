## 1. 显式共同输入（仅本页样例，不是默认值）

| 项目 | 样例输入 |
|---|---|
| 日历 / 时区 | `Asia/Shanghai`；显式合成交易日序列 D0=`2026-09-28`、D1=`2026-09-29`；日内所列桶均标为连续竞价，无午休跨桶 |
| 品种 / 价域 | 合成普通主板股票 X，raw、tick=`0.01`、整手 L=`100`；reference=`10.00`、当日下限=`9.00`/上限=`11.00` 作为显式 facts；不是由固定 band 推算 |
| 覆盖证明 | 所列日/品种的日历、halt、公司行动 attestation 完整；除特别列出外不停牌、公司行动事件为空 |
| 数值 / 费用 | Decimal 金额；A/B/C/D 均**显式设定** `F_buy(N)=F_sell(N)=0`、费用上界=0，到分 `ROUND_HALF_UP`；E 单独定义非零费用模型 |
| 桶 / 参与率 | 桶为 `[start,end)`、end 可见 close/volume 并 match；本页各例显式 `p=0.20`，不代表运行默认 |
| 独立性 | A、B 各行、C、D、E 各自重置初始状态；只计算 fill/残量/现金/预留，不制造收益或净值曲线 |

所有 submit 满足 `available_at <= submitted_at`；未另列的预先订单在表述交易日09:29提交、09:30生效、09:35到期；未标交易日的事件均在D0。需要具体次序时使用表内 submitted_at/sequence/order_id。资源充足也不能绕过资格门。

## 2. A 正例：两单共享容量，partial 后 expiry

初始 cash=`10000.00`、无持仓。O1 BUY 300、O2 BUY 200，limit 均=`10.00`；O1/O2 分别在09:29:00/09:29:01提交，sequence=1/2，均09:30生效、09:33到期。每桶 V=`1000`、close=`10.00`，故 `C=100×floor(0.20×1000/100)=200` 股。

| 事件 / 相位 | 人工推导 | 事件后状态 |
|---|---|---|
| 两单 Accepted | 预留 `300×10 + 200×10 = 5000` | cash=10000，reserved=5000，free=5000 |
| [09:30,09:31) end，先 O1 | `min(300,200)=200`，名义额2000；桶余量0 | O1 PartiallyFilled，残100；cash=8000，reserved=3000，free=5000 |
| 同桶 O2 | 桶已耗200；可成0，**不能再领200** | O2 Accepted，残200；不产 fill，不变现金 |
| [09:31,09:32) end，O1→O2 | 新桶容量200；O1成100，再 O2成100 | O1 Filled；O2 PartiallyFilled、残100；cash=6000，reserved=1000，free=5000；持股400 |
| 09:33 expiry→match | O2 先 Expired，释放 `100×10=1000`；即使第三桶仍有量也不成交 | O2终态残100；cash=6000，reserved=0，free=6000；无额外费用 |

人工校验：增量成交 `200+100+100=400`，名义额4000；每桶双侧总耗量≤200；O1累计300、O2累计100；新买400股在D0不可卖。反答案“首桶 O1=200、O2=200”共用400>200，违反共享容量。

## 3. B 反例：同刻撤/到期优先及迟到订单

以下每行独立：BUY 100、limit=`10.00`、cash=2000、费用0；桶 `[09:30,09:31)`、close=`10.00`、V=1000、C=200。合格预先单接受时 reserved=1000。

| 编号 / 特殊输入 | 正确 expected | 必须拒绝的反答案 |
|---|---|---|
| B1 `expires_at=09:31` | 09:31先 Expired；fill=0、cash=2000、reserved=0 | “close触价，先成100再过期”违反右开 expiry |
| B2 cancel 于09:30:30提交、09:31生效，expiry=09:32 | 09:31先 Cancelled，释放1000；fill=0 | 同刻先 match 后 cancel |
| B3 B1+B2 的 cancel 同刻生效 | 已到右开边界，唯一终态 Expired；只释放一次1000，无 fill/费用 | 两条终态、双重释放或成交 |
| B4 submit=09:30、effective=09:30，expiry=09:32 | 接受并预留，但不满足 `submitted_at < bucket_start`；首桶fill=0；下一桶end=09:32又先到期，最终fill=0 | 把 `<` 放宽为 `<=`，首桶成交 |
| B5 submit=effective=09:30:30，expiry=09:33 | 首桶fill=0；下一桶若仍close10、C200，可在09:32成100 | 用同桶已完成总量支持桶内迟到单 |
| B6 submit=effective=09:31，expiry=09:34 | 09:31在match后接受；[09:31,09:32)也因严格提交门不合格；最早可匹配[09:32,09:33) | 桶尾新单回填刚结束桶，或忽略下一桶的严格提交门 |

## 4. C 正反例：T+1 与可卖量不能重复预留

D0 09:31按合同买入200股，初始无其他 lot；新增 lot 的 sellable_date=D1。D0买后现金充足，卖价/容量均不是限制因素。以下SELL均limit10；D0新单09:32生效、D0 09:35到期；D1两单均D1 09:30生效、D1 09:35到期。

| 事件 | 手算结果 |
|---|---|
| D0 09:32提交SELL 100 | D0可卖=0，Rejected；不得卖出、不得通过缩量“接受0股” |
| D1 09:29提交S1 SELL 200 | 显式日历已进入D1，可卖200；Accepted并预留200 |
| D1 09:29:01提交S2 SELL 100 | free sellable=`200-200=0`；Rejected，不能复用S1预留 |
| D1 [09:30,09:31) close10、C200，S1有效 | S1成200，持股归零；不使用自然日+1推算解锁 |

## 5. D 正反例：双侧共享桶 + 已拒单不复活

初始 cash=0、有200股已可卖 lot。09:28提交 BUY 100、limit10：需1000，故 Rejected。09:29提交 SELL 100、limit10并预留100股；09:31 close10、C200时 SELL成100，cash=1000。先前 Rejected 的 BUY 仍终态；只有09:31 match后**新的** BUY 100 submit（limit10、09:31生效、09:35到期）可用这1000获接受，且不能成交于已开始桶。

独立的双侧容量检查：cash=2000、有100股可卖；预先接受 BUY 200 与 SELL 100，均limit10、有效期覆盖桶尾。即使 BUY 更早提交，09:31 match仍先SELL成100，再BUY只成100；总容量200，BUY残100。cash=`2000+1000-1000=2000`、BUY剩余预留1000。反答案“SELL100+BUY200”耗300>200。

## 6. E 正例：累计最低费只收一次，cancel 不退款

独立输入：cash=`10000.00`、BUY 400、limit=`10.00`，09:29提交、09:30生效、09:35到期。**仅本例**显式费函数：`F(0)=0`；N>0 时 `F(N)=max(5.00, N×0.001)` 到分 `ROUND_HALF_UP`。本例金额均精确到分；仍须另测真正产生舍入差额的输入。BUY未来增量费上界取 `F(N_paid + limit×remaining) - F(N_paid)`；此函数单调，close≤limit保证上界成立。

| 事件 | 累计名义额N / 本次fee_delta | cash / reserved / free |
|---|---|---|
| 接受400股 | 上界 `F(4000)=5`；预留4005 | 10000 / 4005 / 5995 |
| 首桶 V1000、C200、close10：成200 | N=2000，`F(2000)-F(0)=5` | `10000-2000-5=7995` / 2000 / 5995 |
| 次桶 V500、C100、close10：成100 | N=3000，`F(3000)-F(2000)=0` | 6995 / 1000 / 5995 |
| 09:32:30生效cancel残100 | 不新增名义额，fee_delta=0；释放1000 | 6995 / 0 / 6995 |

累计成交300、名义额3000、总费5；`10000-3000-5=6995`。若逐 partial 各扣最低费得到10，或取消时再扣5/退已付5，均错误。相同参数但初始cash=4004，接受时须 Rejected，不自动缩至300股；零成交取消/到期费用为0。
