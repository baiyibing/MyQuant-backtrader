# TopK 分钟执行 P1（#208，2026-09-27）

执行 [计划 §5 P1](plan-topk-exec-model-2026-09-26.md#5-切片)，依据 2026-09-26
人裁 GO。仅共享分钟入口的 `topk_dropout`；不实现 P2/P3/#214，不改日线、
卖出规则、joint_return 或真实档位接线。

| `--topk-exec` | 报价与失败语义 | 买入 reason |
|---|---|---|
| `close`（默认；不传相同） | 原 `_buy_px`：14:55 close；缺行取 14:30–14:55 最后 close，空窗不买 | `pool` |
| `open`（opt-in） | 精确 09:30 open 一次；缺行不借后行 | `pool:open` |
| `intraday`（opt-in） | 按 session 顺序找首次 `open < limit_up`；等于或高于上限时原票继续等 | `pool:intraday` |

session 使用 `ashare_bars._in_session` / `annotate_session` 契约：
闭区间 [09:30,11:30] 与 [13:00,15:00]，排除竞价和午休。缺 09:30 的
intraday 可在稍后的有效分钟尝试；全部有效 open 均封板则记
`limit_retry_expired`，没有有效报价则 `skip_no_bar`。解板后的跌停禁买、
buy_gate、现金、volume 失败结束当日订单，不算重试到期、不找替补。

上限继续来自 `book_limit_prices(..., qlib_limit_pct=0.095)`。新增模式按
计划使用字面 `open < limit_up`，不把旧上限比较的 0.001 epsilon 带到新扫描；
默认 close 的 epsilon 路径不变。下限仍沿既有禁买检查，不接真实档位。

新模式自动进入现有分钟顺序调度，无需另传 `--fix-minute-cash-order`。
开盘持仓决定原 planned 集合，原 `_buy_denom`（含 vacancy slot_count）保留；
09:30 买调度开始时冻结现金基数。每次实际下单继续交给 `run_pool_buys_day`，
使用 `min(日额度,冻结现金)×0.95÷D`，绝不按成功/剩余只数重新分配。
同分钟 open 卖先到账，再买，close 卖后到账。以后卖款只影响实际现金检查，
不增加原额度。整手、补充 100 股与含费用现金检查沿用原账本；现金失败记
`skip_cash`。启用已有 volume cap 时 open 不可使用本分钟尚未完成的量，
沿用 `skip_volume_unavailable:bucket_not_completed`，不会伪装成涨停。

仅 opt-in 产物增加实际成交 `hm`（当天分钟数）以及
`topk_execution.json`。该文件记录原席位/代码、09:30 选择分钟、真实报价/
成交分钟、额度/分母/现金基数、首次涨停阻拦及最终结果，包含
`limit_retry_fills`（先阻拦后实际成交）和 `limit_retry_expired`。
终止失败不重试，跨日不携带订单；无替补名册或递归移交。

CLI HELP 增补独立 `TOPK_EXEC_HELP_LOCK`；默认 summary 的旧 HELP_LOCK、
stats/trades 字段与 run-manifest 配置不加零值/close 字段。新模式 summary
才附加新契约。`vwap` 明确拒绝并指向 P2；无 `--limit-walkdown` 旗。
`topk_score_exit` 拒绝 open/intraday。
