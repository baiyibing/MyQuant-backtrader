## 一、问题定义

给定一段时间内的日线数据和分钟线数据，每天有一份股票名单（来自 `stock_pool/YYYYMMDD.csv`，不是日线全市场）。名单上每出现一次视为独立实例。目标是在**统一卖出规则**下做网格回测，探索全局收益率。

研究边界（确认人原话）：不必参考策略 8 的买卖规则；除每日选股名单和交易所交易规则外，卖出规则可以探索。策略 8 的上证十日线门控、加仓书、档位回撤等**不自动带入**。

### 核心约束（按 §十确认回写；可再改）

| 约束项 | 设定 |
|--------|------|
| 窗口 | 20251023–20260909 |
| 名单 | 仓库根 `stock_pool/YYYYMMDD.csv`（与策略 1–6/8 默认树同一棵；可变，不冻结 `exports/`） |
| 实例 | 名单每出现一天 = 一笔独立实例；已持仓再上名单再开一笔；卖后再上名单还能再买；同时持有笔数无上限 |
| 买入日 | 该实例对应名单日当天 |
| 最早可卖 | T+1：买入当天不能卖，最早下一交易日 |

| 卖出价 | 模式 A = 触发日日线收盘；模式 B = 触发那根分钟的 **close**（high/low 只用来判断碰到没有） |
| 每笔金额 | 目标 100 万；股数按买入价向下取整到 100 股 |

| 指标口径（Q30 已锁定） | **第一排序 = 总收益率**（基数 11 亿）；年化 = (1+总收益率)^(365/322)−1；最大回撤按 11 亿初始净值的每日净值曲线。副指标：每实例平均/中位收益率%、胜率（分母=实例数）、盈亏比、平均持有天数、总 PnL、峰值并发资金。各参数组实际开仓实例数相同，总收益率与每实例平均排序同序，两列互为校验 |

| 退市 / 数据中断（Q33 已锁定 B） | 中断码冻仓到最后收盘价估值（Q5 延伸）；报告附「按 0 计」敏感性一行。预检：3 码中断、9 笔受冻（§9.7），敞口上限 900 万 ≈ 基数 0.8% |
| 期末未平仓 | 按 20260909 收盘估值计入期末净值，**不记一笔强制卖出** |
| 卖出所得 | 回池，后面日子还能买新实例 |
| 复权 | 模式 A：复权日线，不做 E-R6。模式 B：不复权日线收盘买入 + 不复权 1 分钟监控，持仓期除权日做 **E-R6 + 该笔股数 ÷ k**（成本/峰值 ×k，股数 ÷k，总成本不变；成交价仍用不复权价；现金红利仍不入账）。此能力只给本网格，**不改**现 `rescale_position`（1–6/8 仍只改 cost/peak、不动 shares） |
| 实现顺序 | 先只做模式 A；模式 B 后补 |
| 框架（Q27–Q28） | **能用本仓向量化回测框架就用**；允许任何级别重构。只有重构工作量实在太大，才考虑其他开源回测框架。**不要用 backtrader / Cerebro**（本仓已退场，外框退路也不选它）。也不复活 Rolling / Qlib PortAnaRecord |

### 核心难点

不存在一个卖出规则能让每只股票都达到各自的理论最大收益。需要在统一规则框架下，通过参数优化，逼近全局最大收益率。

## 二、卖出规则设计

卖出规则分两阶段：第一阶段**三类**（规则 1–2 已确认 §十 Q23–Q24；规则 3 由 Q31 追加，2026-09-17 晚），第二阶段两类（本轮不做）。

### 第一阶段：Baseline + 主力规则

**规则1：固定持有天数**

| 参数 | 逻辑 |
|------|------|
| N（交易日） | 买入后第 N 个交易日收盘卖。N=1 = 买入后第 1 个交易日（T+1 下最早可卖日）。**交易日 = 市场交易日（Q32）；到期遇停牌顺延到复牌后首个有 K 日执行**，规则 2/3 的 N 封顶同口径 |

模式 A 卖出价 = 到期日复权日线 close。模式 B 尚未实现。

**规则2：止盈 + 止损（同根 K 先止损，否则先到先执行）**

| 参数 | 逻辑 |
|------|------|
| X%（止盈） | 持有期间价格达到买入价 × (1+X%)，触发卖出；可「不设止盈」 |
| Y%（止损） | 持有期间价格跌破买入价 × (1-Y%)，触发卖出；可「不设止损」 |
| N（最大持有交易日） | 超过 N 个交易日强制收盘卖 |

- 模式 A：用复权日线 close 监控并成交（「同根 K 先止损」在 close-only 监控下不可能触发，仅对模式 B 生效——见 §一注记）
- 模式 B（后补）：用不复权分钟 high/low 判断，成交用该分钟 close

**规则3：移动止损（trailing stop，Q31 追加）**

| 参数 | 逻辑 |
|------|------|
| Y%（回撤） | 持仓峰值回落：可卖日 close < peak × (1−Y%) 触发卖出 |
| N（最大持有交易日） | 超过 N 个交易日强制收盘卖 |

- peak = 持有期间至今最高**复权 close**（模式 A），初值 = 买入价；买入日（T+1 不可卖日）close 若更高**计入 peak 但不触发**，从下一可卖日起判定
- 与规则 2 的止损同构（`close < 阈值`），跌停顺延、停牌冻仓（peak 冻结）同样适用；模式 B 后补时 peak 用不复权 close，除权日 `peak × k` 由账本缩放
- 账本 `peak` 现仓已有（`rescale_position` 同步缩放），复用成本≈0

### 第二阶段（视结果决定是否展开；本轮不做）

| 规则 | 逻辑 | 适用场景 |
|------|------|---------|
| 持有期内取最高 | 持有 N 天，期间取最高价卖出 | 理论收益上界参考，有未来函数嫌疑 |
| 均线拐头 | 跌破 M 日均线卖出 | 趋势跟踪，不同股票波动率适配性差 |

## 三、参数空间设计（第一阶段已确认）

### 固定 N 天

| 参数 | 取值 |
|------|------|
| N | 1, 2, 3, 5, 8, 10, 15, 20 |

### 止盈 + 止损

| 参数 | 取值 |
|------|------|
| 止盈 X% | 2%, 3%, 5%, 7%, 10%, 15%，以及 **不设止盈** |
| 止损 Y% | 2%, 3%, 5%, 7%, 10%，以及 **不设止损** |
| 最大持有天数 N | 1, 3, 5, 8, 10, 15 |

全量遍历。规则 1 共 8 组；规则 2 为 7×6×6 = 252 组；合计 **260** 组。比提案原稿多「不设止盈 / 不设止损」。

**规则3（trailing，Q31 追加）**：Y ∈ {3%, 5%, 8%, 10%, 15%} × N ∈ {5, 10, 15, 20} = **20 组**，与规则 1/2 语义不重叠、无重复。

**有效组合数 = 233（评审修正 + Q31，见 §十三 R2.2）**：

- 规则 2 的 **N=1 全部 7×6=42 组**与规则 1 的 N=1 完全等价——无论止盈/止损是否在第 1 个可卖日触发，都以同一根 close、同一日期成交，跌停顺延对所有组同样生效；
- 规则 2「不设止盈+不设止损」× N∈{3,5,8,10,15} 与规则 1 对应 N 重复 5 组（N=1 已计入上一条）；
- 有效 = 8 + 252 − 42 − 5 + 20 = **233**。网格照旧全跑 280 组（260+20，去重只是解读排名时的口径），但报告与本文以 233 为准。

### 参数选择依据（原稿；未再裁）

- 主板日涨跌停约 10%，创业/科创约 20%，故 15% 止盈对 20% 板仍有意义
- 止损小于 2% 易被噪音触发
- 持有天数覆盖短（1–3）、中（5–8）、长（10–20）三个时间尺度

## 四、回测引擎架构

### 两种回测模式

| 模式 | 买入 | 监控 / 卖出 | 价格域 | 本轮 |
|------|------|-------------|--------|------|
| 模式 A | 名单日**复权**日线 close | 复权日线 close | 复权 | **先做** |
| 模式 B | 名单日**不复权**日线 close | 不复权 1 分钟 high/low 触发，close 成交；除权日 E-R6 **且股数 ÷ k** | 不复权 | 后补 |

同一天同一只股票，模式 A 与模式 B 买入价可能不是同一个数字，两套净值不能直接排名。

### 每日执行流程（以下是模式 A；模式 B 后补）

```
for each trading day i:
    1. 卖出检查：遍历当前每一笔独立实例
       - 买入当天：跳过（T+1）
       - 停牌 / 无 K：冻仓
       - 跌停：不卖，下一交易日再评（板块幅度 ±0.2% 容差判定）
       - 用当天复权 close 比止盈/止损/到期；规则3 用 close < peak×(1−Y%)（peak 先更新后判定，买入日只计 peak 不触发）
       触发则按当天复权 close 卖，扣 0.1% 佣金，现金回池
       （「同根 K 先止损」仅模式 B 分钟 high/low 会发生，此处 close-only 不存在双触——§十三 R2.1）
    2. 买入检查：当天 stock_pool/YYYYMMDD.csv 里每一个 symbol
       即使该 symbol 已有未平仓实例，仍再开一笔
       名单日无 K / 停牌：不买（无收盘价可成交）
       买入价 = 当天复权日线 close
       涨停（收盘封板，板块幅度 ±0.2% 容差）：不买、不追
       目标 100 万，股数向下取整到 100 股，佣金 0.1%
    3. 窗口末日 20260909：仍持有的实例按当日复权收盘估值进净值，不记卖出成交
```

### 网格搜索流程

```
for each 参数组合:
    初始化账本（名义现金池 11 亿，Q30；峰值预期 10.53 亿内不触顶）
    遍历窗口每一交易日:
        先卖后买
    计算: 总收益率（基数 11 亿）、年化 (1+r)^(365/322)-1、胜率、
          盈亏比、平均持有天数、每实例平均/中位收益率%、总 PnL、
          峰值并发资金（Q30 锁定的指标口径）

输出: 按总收益率排序的 top 20 参数组合
```

**实现捷径（评审建议，见 §十三 R5.1）**：无限现金 ⇒ 各参数组**入场集完全相同**（5061 笔，见 §9.7）。可先做「`(实例 × 离场策略)` 收益矩阵」的纯向量化求值器（每实例对每策略一个 return%），再聚合排名；逐日循环 + 账本引擎留给以后有上限资金 / 滑点版本。两条路都算「采用本仓向量化框架」。

### 输出报告

| 输出项 | 说明 |
|--------|------|
| 交易明细 | symbol, 实例键（symbol+名单日，见 §十一）, buy_date, buy_price, sell_date, sell_price, profit, return% |
| 参数排名 | 按**总收益率（基数 11 亿，Q30）**排序的 top 20 组合；每实例平均收益率并列展示（同序，互为校验） |
| 绩效汇总 | 总收益率、年化 (1+r)^(365/322)−1、最大回撤（11 亿初始净值每日曲线）、胜率（分母=实例数）、盈亏比、平均持有天数、每实例平均/中位收益率、总 PnL、峰值并发资金 |
| 锚线参考 | ① 持有到期末（不设 TP/SL，N=∞）② N=1 次日即卖 ③ oracle 上界：每实例 T+1 起剔除跌停日的最优离场日收益（明示上界，非可交易规则）④ 退市敏感性：9 笔受冻实例按 0 计时总收益率/排名变化一行（Q33） |

| 单股分析 | 每只股票在各参数下的表现分布 |

## 六、数据口径

不必再交扁平 CSV。实现读本仓库湖和名单。

- 每天名单：`stock_pool/YYYYMMDD.csv`，首列裸六位；**不是**当天日线里所有 symbol
- 模式 A 日线：湖分区 `resolve_period_root("1d") / dividend_type=front`（QMT 前复权；后复权 `back` 日常默认不下）。现成 `load_daily_bars` 读的是 `none`，模式 A **不能**走默认路径
- 模式 B 日线 / 分钟：不复权 `dividend_type=none`；分钟 1 分钟，上界 20260909

### 9.5 E-R6 残留会偏什么、有没有更准的做法（Q29 = B）

确认人问：§八「只修参考价、红利不入账、送转不改股数」是不是导致不精确，有没有更好做法。

**会偏，偏的是钱，不是「该不该卖」。**

E-R6 做的事：不复权 K 在除权日会向下跳。若不改持仓成本/峰值，10 送 10 这种 >5% 跳空会被当成暴跌，假止损。现引擎在除权日把该笔 `cost`/`peak` 乘 k，和当天不复权价同一价域，**触发判断**就对了。宿主 5 亿上，假止损 149→143，净值只多了约 4.5 万——那是「少错杀」的量，不是把盈亏记完整。

现引擎（1–6/8）故意没做、因而仍不精确的（**本网格模式 B 已用 Q29=B 修第一行**）：

| 残留 | 现引擎 | 本网格模式 B（Q29=B） |
|------|--------|----------------------|
| 送转不改股数 | 原股数 × 半价，市值少记约一半 | `shares /= k`，大送转市值能对上 |
| 现金红利不入账 | 不入账 | 仍不入账（要 §9.6 表才升） |
| ≤0.5% 噪声带不修正 | 不缩放 | 仍不缩放（随 E-R6 噪声带） |

湖里的 `ex_date_index` 只有除权日（`dr` 禁用，不参与推导），`adj_factor` 只有一个综合 k。**现成数据分不清「这一跳是送股还是派息」。** 所以「按 k 改参考价」能做；「红利入账 + 送转改股数」要再有拆开的权息明细，或接受用 k 近似（把整个跳变都当成股本变化）。

模式 A 用复权日线、不做 E-R6：涨跌幅接近含权息的连续收益，**没有这三条残留**。问题只在模式 B（分钟只有不复权）。

确认人：**如果能做 B，就 B。** B 能做：k 已由 `load_exdiv_ratios` 给出；除权日在本网格账本上 `cost *= k`、`peak *= k`、`shares /= k`，总成本不变。除权后股数**不再按 100 取整**（避免 10 送 10 后少记一手以内）。现成 `rescale_position` 按 X-R1 不动 shares，本网格另写一条，不改 1–6/8。

现金红利仍不入账（现湖分不开派息 vs 送股）。不声称完整权息账本。要升级到完整账本，必须先有 §9.6 的权息拆分表。

不推荐：用日线复权价去对分钟不复权 high/low（价域混用，比残留更歪）。

E-R5 已写：名单偏高分红/高送转，或结论差距落在 1% 以内时，必须重开这套近似。本网格窗口与策略 8 同窗，幅度分层里 >5% 送转仍是大头。

### 9.6 权息拆分表（完整账本的前置数据；现湖没有）

完整「派息进现金、送股改股数」**不能**从现成 `adj_factor` 的综合 k 或 `ex_date_index` 推出来：

| 现有文件 | 有什么 | 缺什么 |
|----------|--------|--------|
| `adj_factor.parquet` | 每日 `cumulative_adj_factor`，只能算出一个 k | 分不清这一跳是派息、送股、转增还是配股 |
| `ex_date_index.parquet` | `stock_code, ex_date, dr, fetched_at` | `dr` 已禁用、不参与推导；没有每股红利、没有送转比例 |

若以后要从 Q29 = B 升到完整账本，需要另给一张表（CSV 或 parquet 均可），覆盖回测窗内名单并集里发生过除权除息的股票。建议一行一个事件、同一天多事件可多行。

**必须有的列**

| 列 | 含义 | 例 |
|----|------|-----|
| ex_date | 除权除息日，与交易日同一套日历 | 2026-06-18 |
| symbol | 与引擎同一口径，`600519.SH` 或裸六位（需声明） | 600519.SH |
| cash_div | 每股现金红利（人民币）。没有派息写 0 | 0.85 |
| bonus_ratio | 送股：每 1 股送多少股。没有写 0 | 0.3 表示 10 送 3 |
| transfer_ratio | 转增：每 1 股转增多少股。没有写 0 | 0.2 表示 10 转 2 |
| cash_div_is_taxed | 红利是税前还是税后入账 | pretax / aftertax |

**有配股才必须有的列**

| 列 | 含义 |
|----|------|
| rights_ratio | 每 1 股可配多少股；没有配股写 0 |
| rights_price | 配股价；无配股可空 |

**可选但有了更好对账**

| 列 | 含义 |
|----|------|
| event_id | 同一天多事件时的稳定键 |
| announce_date / record_date | 公告日 / 股权登记日（实现按 **ex_date** 入账，这两列只供核验） |
| source | 数据来源，便于对账 |

**入账规则（有了这张表才执行；本轮不执行）**

1. 除权除息日、该笔已持仓：`现金 += shares × cash_div`（税按 `cash_div_is_taxed`；若给的是税前、未写税率，税率必须另定，不能猜）。
2. `shares *= (1 + bonus_ratio + transfer_ratio)`；若 `rights_ratio>0`，是否缴款配股、现金够不够，必须另定，不能猜。
3. 每股成本、峰值按送转后股本重摊，使总成本不变（配股另计缴款）。
4. K 线仍用不复权价。不得再用综合 k 代替本表。

没有这张表之前：模式 B 只做 Q29 = B（`shares /= k`），**不写**派息进现金。模式 A 继续走复权日线，不依赖本表。

确认人要求把「完整账本要权息拆分表」写进本文（2026-09-17）。表可以后补，不挡模式 A。
