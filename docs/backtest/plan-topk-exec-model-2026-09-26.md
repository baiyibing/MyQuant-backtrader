# 计划：topk 分钟执行模型开关（open / intraday / vwap）+ 涨停替补（2026-09-26）

> **状态**：plan 起草，待人裁。批准后按 §5 切片实现；不改任何默认。
> **动机（2026-09-25 实测）**：同 pred（8a061ea4）同闸同 sizing，2025 年日线收盘 +102.25% vs 分钟开盘 +30.03%，差额主通道 = 开盘涨停拦截 4402 次（vs 日线 60 次）。现行"开盘一笔 + 统一 9.5% 板 + 拦截不替补"是三重保守叠加，测的是下界；行业惯例是日内分批执行（TWAP/VWAP、避开开盘竞价后数分钟）+ 真实档位判定 + 区分封死/开板。本计划把执行模型做成**显式研究开关**，量出"执行模型敏感带"。

## 1. 三根轴（互独立、全部默认关）

| 轴 | 旗标 | 取值 | 语义 |
|----|------|------|------|
| A 执行时点 | `--topk-exec` | `open`（默认=现状） | 现行：09:30 开盘价一笔，全成或全不成 |
| | | `intraday` | 开盘被涨停规则拦下后**不立即放弃**：沿当日分钟 bar 找**首个 open < 涨停价**的分钟，按该分钟 open 成交；全天未开板 → 收盘作废（A 股订单当日有效，与实盘一致） |
| | | `vwap` | 09:35–14:55 窗口内按该票分钟成交量分布切片下单（P2 再做；先 open/intraday） |
| B 涨停档位 | ——（不在本计划） | | **X-07 真实档位（10/20/30/ST 5%）归修复专题**（#202 后续刀）；本计划消费其成果、不重复实现。X-07 合入前后 `--topk-exec` 均可用，只是拦截判定精度不同 |
| C 拦截替补 | `--limit-walkdown` | 默认关 | 开（人裁项）：当日买单向被涨停拦死且执行模型仍无法成交时，其额度沿当日排名 walk-down 给下一名合格票（复用 ST/年龄闸的 walk-down 机制）；关=现行额度闲置 |

## 2. 语义细节（防歧义）

1. **分母不变**：每票额度仍 = `min(日额度,现金)×0.95 ÷ 当日 planned 只数`；intraday/walkdown 只改"这份额度花不花得出去"，不改分配公式（与 #205 配对解耦）。
2. **intraday 成交价**：目标分钟自身的 open（不造价、不跨 bar；该分钟 open==涨停价仍视为在板上，继续等下一分钟）。
3. **可追溯**：trades 的 `reason` 前缀区分 `pool`（开盘即成）/`pool:intraday`（板开补买）/`pool:walkdown`（替补）；stats 新增计数 `limit_retry_fills / limit_retry_expired / walkdown_fills`。
4. **卖出侧不动**：dropout 当日收盘卖、跌停 pending 语义原样；本计划只改买侧执行。
5. **日线引擎不动**：日线收盘成交是它自己的身份；本计划全部在分钟入口（`csv_minute_backtest.py` + simulate 循环的 topk 路径）。

## 3. 验收锚

1. **回归锚**：`--topk-exec open`（不传=同）在 2025 stag15 锚配置下**逐字节复现** 2026-09-25 终版（+30.03%，期末 130,026,590.28，拦截 4402，买入 1058）。
2. **合成测试**：一字板全天不开 → 零成交且计数 expired；开盘板 10:30 开板 → 恰在 10:30 分钟 open 成交；vwap 切片成交额合计=额度；替补开时下一名拿到的额度=被拦者额度。
3. **产物纪律**：所有 fill 价必须落在对应分钟 bar 的 open 上（反造价断言）。
4. **敏感带交付**：2025 锚配置 × {open, intraday, vwap} × {walkdown on/off} 六格对照表（收益/回撤/成交数/拦截expired/替补数）+ **2026 窗交叉验证**（避免 2025 单窗过拟合结论）。

## 4. 边界与不做

- 不改任何默认（`--topk-exec` 默认 `open`、walkdown 默认关）；
- 不实现真实档位（X-07 归属修复专题；两刀正交，接口=涨停价判定函数）；
- 不做排队/封单量概率模型（行业有，但先做确定性开关；打板/排板风格明确不做）；
- 不动 joint_return 回放核、不动生产 fill/fee；
- `topk_score_exit` 是否同享开关：P1 先只挂 `topk_dropout`，P3 视结果再裁。
