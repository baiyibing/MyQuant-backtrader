## 1. Python vs Rust 性能对比

### 1.1 全市场耗时（2026-05-25，window=1000，step=0.01）

| 维度 | Python | Rust | 倍率 |
|------|--------|------|------|
| 数据加载 | DuckDB persistent 16.6s | polars batch 9.8s | Rust 1.7x |
| Capital 预加载 | DuckDB SQL 1.0s | HashMap 0.1s | Rust 10x |
| 计算（并行） | ProcessPool 7 核 | rayon 8 线程 | — |
| **总计** | **~7.5min** | **~3.9min** | **Rust 1.9x** |
| 输出股票数 | 4594 | 5513 | Rust 多 919 只 |

### 1.2 优化历程对比

| 阶段 | Python | Rust |
|------|--------|------|
| 原始版本 | ~30min（`np.apply_along_axis` ×4 + pandas filter） | ~1.8min（单口径，fat LTO） |
| 第一轮优化 | numba batch curpdf + ProcessPool → ~15min | curpdf 复用（circ+free 共享）→ -9% |
| 第二轮优化 | DuckDB persistent + capital dict → ~10min | polars batch parquet → -13% |
| 第三轮优化 | 4-way cumpdf 合并 → **~7.5min** | 精度修复 + 双口径 → **~3.9min** |
| **总加速** | **~4x** | **功能增强后仍 2x Python** |

### 1.3 技术栈对比

| 环节 | Python | Rust |
|------|--------|------|
| 三角分布 | numba `@jit(nopython=True)` | 纯 Rust + 编译器自动向量化 |
| 衰减累积 | numba batch `_batch_cumpdf_4way` | `calc_cumpdf_decay_window_scaled` FMA 循环 |
| 并行 | `ProcessPoolExecutor`（进程级） | `rayon::par_iter`（线程级） |
| 数据加载 | DuckDB SQL → pandas DataFrame | polars lazy scan → 自定义 `BarRow` |
| 资本查询 | DuckDB `ROW_NUMBER()` → 4 个 dict | `load_free_float_shares` → HashMap |
| 价格网格 | `make_price_grid`（逐点乘法） | `min_p + i as f64 * step`（逐点乘法） |

## 3. 关键工程约定

### 3.1 价格网格构建

**禁止使用** `np.arange(min_p, max_p + step, step)`。

**必须使用** `make_price_grid(min_p, max_p, step)`（Python）或 `min_p + i as f64 * step`（Rust）。

原因：`np.arange` 内部逐步累加 `current += step`，浮点误差线性累积。详见 `Rust-Python换手阻力精度差异—权威根因分析报告.md`。

### 3.2 Capital 口径

| 口径 | T 窗口 | T-1 窗口 |
|------|--------|----------|
| circulating | `circ_cap_t`（T 日） | `circ_cap_prev`（T-1 日） |
| free-float | `free_cap_t`（T 日） | `free_cap_prev`（T-1 日） |

Python 和 Rust 必须各自加载 T 和 T-1 两天的 capital，不可混用。

### 3.3 验证流程

修改算法或精度相关代码后，必须执行：

1. `cargo fmt -- --check && cargo test --all-targets && cargo clippy --all-targets`
2. 全市场端到端对比（`rust-python-e2e-verification` 流程）
3. 确认 cyqk_T 和 cyqk_T_1 差异 > 1e-6 的股票数 = 0
