# TopK 分钟执行 P3（#208，2026-09-27）

依据 2026-09-27 人裁 GO，落实 [计划 §5 P3 / §2.3–§2.4](plan-topk-exec-model-2026-09-26.md)。
本说明是本次冻结契约的实现 SSOT。共享分钟入口新增 `--limit-walkdown`，
默认 OFF，仅 `topk_dropout`；`topk_score_exit` 及其他书显式拒绝。
`vwap × --limit-walkdown` 在 CLI / run / simulate 验证阶段硬拒绝。

首次有效尝试被涨停拦截就移交席位，原票当天退出，不等全日失败，不再复活。
原 planned（含 keep_buy_vacancy 的 slot_count）确定分母 D；
`q=min(daily_quota,cash_basis)*cash_deploy_frac/D` 冻结一次。候补拿整份 q，
不再除 D，不合并其他空位额度，仍走现有整手、费用、现金及量约束。

| exec | walkdown ON |
|---|---|
| close | 14:55 单次决策递归替补，各票 `_buy_px` close 及 14:30–14:55 回退；实际 quote_hm 单独记录 |
| open | 09:30 决策递归，仅精确 09:30 open；候补缺行记 skip_no_bar 后继续链，不借后行；原票缺行不触发替补 |
| intraday | 首次涨停时刻 t 即移交；候补只看 hm >= t 的 session open，缺 t 可等下一根；候补再次涨停则以新时刻继续链 |
| vwap | 显式拒绝，未定义多片/部分成交移交 |

当日候补按同一分数规则冻结排序并沿用买入资格闸，只向当前票排名之后走。
排除开盘持仓、当前持仓、原 planned、当天已选候补（包括已成交/失败候补）。
每个候补最多选择一次，链长不超过合格名册；耗尽记 `walkdown_exhausted`，
余款闲置。ST/年龄/15% 补位和均线留空仍先在计划阶段完成，不借此旗填其他空位。

自动进入现有分钟资金调度，同分钟按原 planned 顺序处理完整席位链。
open/intraday 在 09:30 买调度冻结 cash_basis，open 卖先到账、close 卖后到账；
close 在 14:55 close 买调度冻结，沿用该阶段卖先买后的顺序。
每次候补实际执行时检查含费用现金，不能预借后续卖款；现金失败 `skip_cash`
终止链。跌停、buy_gate、volume 等失败也终止链，不算涨停替补成功。
缺报价 `skip_no_bar` 与 intraday 无剩余分钟 `skip_no_remaining_bar` 分开记录，
不跨日，不记为同票涨停 retry expired。现有 qlib 9.5% 档位保持不变；
close 沿用旧 epsilon，open/intraday 沿用严格上限比较。

候补成交 reason 固定为 `pool:walkdown:close` / `pool:walkdown:open` /
`pool:walkdown:intraday`。原票直接成交沿用该模式 reason。
opt-in `topk_execution.json` 扩展 seat、original_code、substitute_code、
selection_hm / decision_hm / quote_hm / execution_hm、quota、denominator、
allocation_cash、price、phase 及具体结果；`walkdown_selected` 记录移交。
`walkdown_fills` 只计候补实际成交，`walkdown_exhausted` 计候补耗尽次数。P1 的 `limit_retry_fills` / `limit_retry_expired`
仍只表示 walkdown-off 的同票重试；已移交代码不计 expired。
