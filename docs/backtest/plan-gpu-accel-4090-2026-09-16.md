# Plan：4090 加速判定与分阶段方案（S0 实测 → 判定门 → 条件切片）

> **落盘**：2026-09-16。
> **状态**：📄 **v1.0 · 提案，待多 agent 评审 + 待人裁 GO**（本文件未评审；人裁后按裁决推进或关闭）。
> **风险档**：**L1**（S0 只读测量；S1 跑法层面；S2/S3 均为可选 backend / 另开 plan，不碰成交核）。

> **上游证据**：PR #57 [repo-analysis-opus5-next-2026-09-15.md](repo-analysis-opus5-next-2026-09-15.md) §4（#54 分钟 simulate profile：卖环 75.51% / 编排 18.61% / chase 0.01% / pool buy 4.99%；numba trail 结构性不可达 L638-644/L851）；[chip/h14-d1-minute-chip-profile-results-2026-09-15.md](chip/h14-d1-minute-chip-profile-results-2026-09-15.md)（`minute_chip_distribution` ~50.7 ms/call）；[engine-positioning-ssot.md](engine-positioning-ssot.md)；H15 numba backend + parity 先例（`oskh_factors/chip/core.py`、`tests/test_minute_chip_numba_parity.py`）。
> **前置**：S0 与在飞 PR（#58/#59）无冲突（只读）；S2/S3 排在 #58/#59 合入之后（S3 动同批文件）。

## 0. 一句话

**单次回测不值得 GPU**（瓶颈是分支状态机卖环 + IO，量级分钟级）；4090 的正确用法按判定矩阵走三处：**全市场筹码核（CuPy）→ 参数网格（CPU 多进程）→ （条件成立才做）卖环 compiled scan**；本 plan 先只批 S0 实测定标，S1–S3 由判定门逐级放行。

## 1. 证据与量级

| 事实 | 出处 | 推论 |
|------|------|------|

| `minute_chip_distribution` ~50.7 ms/call（Python）；全市场扫描 = 数千码 × 长窗 | H14/D1 profile | 全市场筹码扫描是**小时级 CPU** 任务；直方图原子累加是 GPU 教科书负载（S2 候选） |
| numba 已是依赖（H6 CI 断言 `import numba`）；chip 核已有 `use_numba` 开关 + parity 金测试 | `oskh_factors/chip/core.py:88-128`、`tests/test_minute_chip_numba_parity.py` | GPU 后端照抄既有 backend/parity 模式，工程起点非零 |
| Rust TR（`turnover-resist/`） | 引擎 SSOT | 已快且是 SSOT，不动 |

| Rust TR | — | — 不动 | SSOT |

## 8. 风险

- **显存边界**：全市场分钟窗（~5,000 码 × 240 日 × 240 bar × 8 列 × 8B ≈ 18GB）贴近 4090 的 24GB——S2 必须按码分批进显存，禁止整窗常驻。
- float 求和顺序漂移：A-R4 已锁处置（int bin / 容差）。
- Windows + vanna312 + CuPy wheel 兼容性：S2 第一件事是 `pip install cupy-cuda12x` + `import cupy` 冒烟，失败即回退 numba CPU 路线并在短记记录（不强行源码编 CUDA）。
- "未实测就上 GPU"的反向风险：本 plan 的存在理由就是防它——S0 数字之前任何人不得引用预期加速比立项。
