# TopK 分钟执行 P2（#208，2026-09-27）

依据 2026-09-27 人裁 GO，落实 [计划 §5 P2](plan-topk-exec-model-2026-09-26.md#5-切片)。
本说明是冻结分片契约的实现 SSOT。仅共享分钟入口 `topk_dropout` 的 opt-in
`--topk-exec vwap`；默认仍为 close。

CLI 名为 vwap，但实际为**等名义金额、固定时钟的 TWAP-style 研究分片**，
不是成交量参与 VWAP，不按 amount/volume 报价，也不是策略 8 的
`--tail-window-buy`；不复用 `tail_window_buy.py` / `TAIL_MINUTES`。

- 先用 `ashare_bars._in_session` 过滤，再收紧到闭区间
  [09:35,11:30] ∪ [13:00,14:55]。不含竞价、午休、09:30 或 15:00。
- `VWAP_SLICE_CLOCKS` 固定为 09:35、10:30、11:30、13:00、14:00、14:55，
  无分片数配置。精确匹配各时钟，只用该 bar 的有效正数 **open**；
  缺 bar / 非有限或非正 open 该片跳过，绝不借前后行或补造分钟。
- 09:30 买调度开始时冻结 cash_basis（同分钟 open 卖先到账、close 卖后到账），
  `q=min(daily_quota,cash_basis)*cash_deploy_frac/D`；D 为原 planned 分母，
  含 vacancy slot_count。每片预算均为 q/6，合计 q；后来卖款不扩大 q。
- 每片走原 `run_pool_buys_day` / `execute_buy` 账本，整手向下取整，费用另受
  实际现金约束；新增可选 `order_budget` 禁止不足一手补 100 股。每席位追踪
  spent，剩余额度为额外上界。缺失、受限及整手余款留现金，不滚入后片。
- 首片成功后，仅该原席位后续分片允许累加同码持仓；每次成功均独立产生
  `BUY reason=pool:vwap`，持仓保留账本既有同码多 lot 结构。
- 严格 `open >= limit_up` 跳过该片，继续剩余时钟，无 0.001 epsilon；
  qlib 0.095 band 不变。跌停、buy_gate、现金及量限制也仅结束当前片。
- volume cap 使用 `hm-1` 的已完成分钟量桶，`volume_at=hm-1`；不借用本片
  open 时尚未完成的量。缺量/受限按具体 volume 原因记录，后片继续。

仅 opt-in `topk_execution.json` 增加六条逐片事件（即使全缺 bar），包含
原席位/代码、slice_index（0–5）、slice_hm、09:30 selection_hm、decision_hm、
quote_hm、成功时 execution_hm、quota、slice_budget、allocation_cash、
denominator、reason、price、phase。无有效报价时 price / quote_hm 为空。
15:00 追加 phase=close 的席位汇总，不含 slice_budget，以免重复统计预算。

席位至少一次 BUY 即成功，汇总 reason=pool:vwap；零成交且全部有效报价均受
上限拦截时记一次 skip_limit_up（缺失时钟不改变此判定）；全无有效报价记
skip_no_bar。混合失败取**最后有报价的片的具体终止原因**，缺失时钟不覆盖
先前执行失败；逐片完整原因均保留。普通 skip 计数按零成交席位汇总，量约束
仍保留账本的逐次诊断计数。vwap 不增加 limit_retry_fills / limit_retry_expired，
它们保持 P1 intraday 原票重试含义。

[计划 §2.4](plan-topk-exec-model-2026-09-26.md#24-intraday--walkdown-的组合本版明确选择首次拦截)：
**vwap × `--limit-walkdown` 显式拒绝**，直至独立人裁 GO 定义部分成交移交；
HELP 已声明拒绝。本片无 `--limit-walkdown` 参数、替补名单或递归，不实现 P3。

默认 close 字节复现不变，原 master-close golden fixtures 未改；open/intraday
成交行为保持 #218，沿用 [P1](topk-exec-p1-2026-09-27.md)。默认 summary HELP_LOCK /
run-manifest 不新增 topk_exec 或零值字段。新模式自动启用分钟资金顺序调度。
不涉及 #214 / Q8 / 生产默认切换 / joint_return / 日线引擎或卖出路径。

验证覆盖六时钟预算、open 报价、同席位累加、整手/费用现金界、缺行不借价、
session 过滤、分片限价/买闸/量约束、原分母和 09:30 冻结、CLI 落盘以及 P1
默认字节锚。完整 2025 stag15 输入与 hash 未在本机核验；留作有湖主机 follow-up，
不报告未经复跑的 NAV。
